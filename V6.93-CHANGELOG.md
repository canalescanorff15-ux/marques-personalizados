# V6.93 — Cloudflare Workers como produção principal

## Objetivo

Migrar a hospedagem principal do Merlin Encantos em Papel do Netlify para Cloudflare Workers sem alterar as autoridades de dados já estáveis: Neon continua como PostgreSQL e Cloudflare R2 continua como storage S3-compatible de mídia/backup. O Netlify permanece apenas como rollback temporário.

## Implementação

- migração oficial de Next.js 16 para Workers usando `vinext` + `@vinext/cloudflare`;
- `vite.config.ts` com `@cloudflare/vite-plugin` e `cdnAdapter()`;
- `wrangler.jsonc` com Worker `merlin-encantos-em-papel`, `nodejs_compat`, Static Assets, Workers Cache e metadata de versão;
- Static Assets em `dist/client` para não consumir CPU do Worker quando não necessário;
- KV não é obrigatório nesta release porque o projeto não usa data cache persistente (`use cache`, `unstable_cache`, `revalidateTag` ou `revalidatePath`);
- Cloudflare Images não é obrigatório na primeira publicação; as imagens comerciais atuais já são WebP e podem ser servidas como assets/R2;
- comandos dedicados `dev:vinext`, `build:vinext`, `start:vinext`, `deploy:vinext` e `check:cloudflare`;
- novo contrato executável `cloudflare-workers-contract-check.mjs`;
- workflow permanente `Cloudflare Workers Compatibility` com audit, contrato, TypeScript, build Next, build vinext e dry-run real de deploy;
- identidade de release aceita `WORKERS_CI_COMMIT_SHA` como fallback de build, mantendo `COMMIT_REF` somente para rollback Netlify;
- UI de mídia deixa de orientar configuração no Netlify e passa a orientar variáveis/segredos do Worker;
- `NETLIFY.md` rebaixado para runbook de rollback;
- novo `CLOUDFLARE.md` com configuração de Workers Builds, secrets, Neon, R2, primeira publicação e rollback;
- README, RELEASE-CHECKLIST e RUNSITE sincronizados com a nova autoridade de hospedagem.

## Compatibilidade comprovada

O `vinext check` oficial encontrou **93% de compatibilidade**: 6/6 imports Next usados estão suportados, incluindo `next/navigation`, `next/link`, `next/image`, `next/dynamic`, `next/headers` e `next/server`. O único requisito estrutural detectado era `type: module`, aplicado pelo bootstrap oficial. A otimização de imagens é suporte parcial, mas não bloqueia a publicação porque a V6.93 não depende do Cloudflare Images.

O build real passou pelos dois caminhos:

- `next build` — referência/rollback;
- `vinext build` — Cloudflare Workers, incluindo RSC, SSR e client bundles.

O dry-run oficial de deploy também passou com `npm run deploy:vinext -- --skip-build --dry-run`.

## Dependências alinhadas

A migração preserva React 19.2.8 e alinha `react-server-dom-webpack` em 19.2.8. `@types/node` sobe para 22.20.1 para compatibilidade com Vite 8, sem mudar o runtime Node 22.23.2. As versões diretas do stack Workers ficam pinadas no lockfile.

## Dados e segurança preservados

- nenhum schema Neon foi alterado;
- nenhuma tabela/dado foi migrado ou apagado;
- buckets R2 não foram recriados nem movidos;
- lifecycle de mídia, tombstones, backups V9 e DR permanecem intactos;
- Admin/MFA, CSP, CSRF, idempotência, concorrência e contratos existentes continuam fazendo parte do CI;
- `netlify.toml` permanece apenas como fallback até homologação do Workers.

## Gate de promoção

A V6.93 só deve chegar à `main` depois de:

1. Cloudflare Workers Compatibility verde;
2. CI completo do projeto verde no PR;
3. build Next e vinext verdes;
4. dry-run de deploy Workers verde;
5. nenhuma regressão de Neon/R2/segurança.

A criação do Worker e o cadastro dos segredos reais continuam sendo ações de conta da Cloudflare e não são serializados no repositório.
